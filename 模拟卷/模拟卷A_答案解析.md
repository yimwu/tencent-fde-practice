### 1 · 单选

诊断 Agent 的 Prompt 已写“输出 JSON”，实际接入客户系统时仍出现缺字段、类型不符，导致解析失败。Harness 最应补齐哪项能力？

- A. 错误处理：为接口超时和空结果设计重试、降级与转人工分支
- B. 工具接入：补充可调用 API 定义，让模型能获得诊断所需外部信息
- C. 输入输出契约：定义必填字段和类型，并在输入输出边界执行校验
- D. 可观测：记录日志、链路耗时和指标，支持问题回溯与定位

**答案：C**

Prompt 写了 JSON 只是生成要求。接入系统的结构保证还需输入输出契约，明确 Schema 并执行校验；不能把日志或超时兜底当成格式契约的替代品。

- **A**：错误兜底重要，但不能替代对正常输出的字段结构和类型验证。
- **B**：工具接入解决能否调用外部能力，不直接保证交付 JSON 字段与类型合规。
- **C**：缺字段和类型不符正是契约校验应在系统边界发现并处理的问题。
- **D**：观测能暴露问题，仍需契约校验才能约束系统接收的数据结构。

一位业务专家不会编程，想走 Echo/FDPM 路线，能访谈并设计测试用例。结合 FAQ，其最低实践要求是什么？

- A. 先独立掌握所有后端技术，再参与客户需求判断
- B. 只要能解释产品定位，就能省去实际原型验证
- C. 会用平台亲手把想法做成可点击、可运行的原型

- **A**：课程允许能力分工，并未要求人人精通全部后端。
- **B**：定位讲解不能替代将需求落为可运行产物的能力。
- **C**：不会编程可用平台实现原型，满足 FAQ 的动手底线。

### 3 · 单选

某项目报告把“回答准确率、P95 响应时间、四周留存率、来源可追溯”依次列为四项验收指标。按课程四维框架，它们对应的维度依次是什么？

- A. 效果、效率、采纳、合规
- B. 效果、采纳、效率、合规
- C. 效率、效果、合规、采纳
- D. 合规、效率、采纳、效果

**答案：A**

四维分别回答对不对、快不快、用不用、安不安全。准确率衡量效果，P95 衡量效率，四周留存检验持续采纳，可溯源保障合规审计，不能因为四项都是数字就归入同一维度。

- **A**：准确性、速度、持续使用与可审计性分别对应四维。
- **B**：响应时间属于效率，留存属于采纳，二者不能互换。
- **C**：该映射混淆了业务质量、性能、持续使用和合规要求。
- **D**：准确率是效果，来源标注的审计属性归于合规。

- B. 让其负责业务规则调优、复杂问题辅导和新人培养

- **B**：把业务经验投入 AI 调优和团队教练，匹配策略。
- **C**：排除参与会加重被替代感，未形成新的价值来源。

### 5 · 单选

方案的连接器链路已跑通，但业务部门仍拒绝接入其数据。项目经理认为技术可行即代表方案可行。按方案设计期边界，应如何判断？

- A. 将部门异议记为模型能力不足，改用更强模型即可
- B. 工具可提供技术可行性依据，业务可行性由人结合组织判断
- C. 让可视化工具再画一遍链路，就能自动解决部门异议
- D. 连接器已成功取数，就可跳过业务确认进入自动化上线

**答案：B**

技术可行与业务可行不同。连接器能取数只说明技术链路成立，部门是否接受、数据权限是否合理以及隐性诉求，需要人处理；工具可以整理依据或画流程，不能据此替业务方批准方案。

- **A**：异议来自组织与数据接受程度，换模型不解决该根因。
- **B**：数据链路成功不代表业务接受，组织判断仍由人负责。
- **C**：图能辅助沟通，无法自动承担相关方管理和组织取舍。
- **D**：授权与接受程度未达成，技术成功不足以代替业务判断。

公司选定了流程有共性的深耕客户，也已积累头部项目经验，但中腰部团队每次仍从零开始。按试金石的前提条件，当前最突出的缺口是什么？

- A. 工程师应取消抽象，全部改用客户私有配置
- B. 团队应把客户案例数作为唯一能力增长指标
- C. 公司缺少将头部经验传递并复用的机制
- D. 客户缺少业务参与，应退出当前行业

**答案：C**

- **A**：私有配置会削弱跨项目复用，与目标方向相反。
- **B**：案例数不能代表经验可传递或现场投入下降。
- **C**：头部经验无法传到中腰部，直接指向组织复用机制。
- **D**：题设没有业务缺席证据，反而已确认深耕条件。

工程师愿意分享岗位方法，但担心成果匿名入库、复用后无人知道原作者。要正面回答其“贡献”疑问，最直接的机制是什么？

- A. 为 Skill 与踩坑记录保留署名，复用时标注来源
- B. 让 AI 自动改写全部方法，统一归为系统生成
- C. 要求每周必须交固定数量的 Skill，不记录调用效果
- D. 承诺未来会统一奖励，但暂不保存作者信息

- **A**：署名和来源让贡献可追溯，直接回应贡献是否被记录。
- **B**：抹去作者来源会削弱贡献可见性，违背信任机制方向。
- **C**：数量要求没有解决归属，还可能鼓励低质量产出。
- **D**：没有记录支撑的承诺难以让贡献可追溯和被认可。

- A. 请增加自动回复条数，条数越多就视作成功
- B. 请指定客服专家头像，让体验更接近真实坐席

- **C**：推迟效果口径会使后续验收缺少共同基线。
